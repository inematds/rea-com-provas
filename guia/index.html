Em resumo

O REA com provas é um kit aberto e gratuito para quem usa um agente de IA (Claude Code, Codex ou o harness dsh) para estudar um app e fazer a própria versão. REA vem de Reverse Engineer Anything, uma ferramenta aberta de engenharia reversa: entender como um programa foi feito olhando o que já está pronto. O problema: o agente diz que entendeu como o app funciona e inventa o que não viu. O kit traz 4 regras, 3 pedidos prontos (painel de agentes, reator de leads e site refeito) e um conferidor em Python que reprova o arquivo de provas quando falta prova. Para usar, você precisa de Python 3 e de um agente de IA no terminal.

⚠️ Segurança e licença — leia antes

  • Só software seu ou open source cuja licença deixa estudar (MIT, Apache-2.0, BSD, GPL, MPL…). App fechado de outra empresa: não use este método nele.
  • Estudar não é copiar. A sua versão é escrita do zero, com seu nome, seus textos e seu visual. Nada de levar arquivos, ícones ou marca.
  • Licença GPL/AGPL: se reaproveitar qualquer trecho, siga as condições dela. Na dúvida, leve só a ideia.
  • Rode o agente numa pasta separada, sem senhas, chaves ou dados de clientes. O kit só lê e escreve arquivos na pasta do trabalho; nada é enviado, apagado ou publicado sozinho.

O kit é MIT. Texto completo das regras: REGRAS.md.

O que é

Pedir a prova muda o que o agente entrega

Sem prova, o agente escreve um parágrafo convincente. Com prova, cada frase aponta para um arquivo e uma linha que você pode abrir.

✗ Sem prova 
C1. O app usa uma arquitetura moderna
    baseada em microsserviços.
    Confiança: alta

Soa bem. Você não tem como conferir. Às vezes é verdade, às vezes é chute.

✓ Com prova 
C1. Cada agente é um cartão numa grade
- Prova: `src/components/AgentGrid.tsx:12-48`
- Trecho: `repeat(auto-fill, minmax(280px, 1fr))`

Você abre o arquivo na linha 12 e vê. Se não estiver lá, o agente errou.

As 4 regras

O método inteiro cabe em quatro regras

Cole-as junto com qualquer pedido de "estuda esse app e faz o meu".

1

Peça o provas.md

Cada conclusão com o arquivo e o trecho que a prova, mais a seção "O que NÃO deu para provar".

2

Foco no código do app

Mande ignorar node_modules, vendor e site-packages. Provar com biblioteca é explicar a biblioteca, não o app.

3

Só o que é seu ou aberto

Software seu ou open source com licença que deixa estudar. Depois, a SUA versão, com seu nome e visual.

4

Descreva o visual

Cores com código, fontes, movimento e densidade num brief de design. É o que separa painel feio de tela boa.

Como funciona

Primeiro a prova, depois o código

Todo pedido do kit tem duas fases. O agente só constrói depois que o conferidor aprova o arquivo de provas.

Você escolhe o app (seu ou aberto)→ Agente estuda→ provas.md→ confere_provas.py→ APROVADO?→ Brief de design→ A sua versão
3 construções prontas

Três pedidos para colar no agente

Em português, com [colchetes] onde você troca pelo seu caso. Funcionam no Claude Code, no Codex ou no harness dsh. Os agentes das construções são simulados: nada chama IA, API ou manda mensagem de verdade.

🧩 A · Painel de agentes

Estuda como um app open source mostra vários agentes lado a lado e constrói um painel com 6 agentes vivos para um negócio.

  • Exemplo: clínica odontológica — captação, caixa de entrada, SEO, agenda, suporte, relatórios
  • Cada cartão diz o que o agente faz e o estado (com rótulo, não só cor)
  • Caixa de comando que manda a tarefa ao agente certo

prompts/a-painel-de-agentes.md

⚡ B · Reator de leads

Estuda como um app open source divide um pedido em tarefas para agentes trabalhadores e constrói o fluxo de leads.

  • Lead entra → qualificar → responder → agendar → acompanhar (4 raias)
  • Lead que não qualifica sai com o motivo escrito
  • Comemora na tela quando o lead agenda

prompts/b-reator-de-leads.md

🌐 C · Site refeito

Mapeia o SEU site (seções, fontes, scripts, botões) e refaz numa versão premium com as suas palavras.

  • Jeito 1: salvar a página com curl, sem instalar nada
  • Jeito 2: o REA olha a página aberta num Chrome local
  • Mesmos botões e destinos; sem inventar preço ou promessa

prompts/c-site-refeito.md

O conferidor

confere_provas.py reprova o chute

Um arquivo Python, só biblioteca padrão, sem internet. Lê o provas.md e devolve nota de 0 a 10, APROVADO ou REPROVADO e a lista do que falta. Sai com código 0 (aprovado), 1 (reprovado) ou 2 (não conseguiu ler).

Reprova quando

  • falta a seção "O que NÃO deu para provar" (ou ela está vazia);
  • uma conclusão não cita arquivo/trecho (ex.: src/arquivo.ts:40-62);
  • todas as referências apontam para bibliotecas (node_modules, vendor, site-packages, dist, build, arquivos .min.js…).

Avisa (sem reprovar) quando

  • a prova não diz a linha;
  • uma conclusão só cita biblioteca, mas outras citam o app;
  • falta a linha "Licença:" na seção "Alvo";
  • o título ainda tem [colchetes] do modelo.

O exemplo ruim do repositório, conferido (o conferidor responde em português):

python3 confere_provas.py exemplos/provas-ruim.md
NOTA 0/10 — REPROVADO
Conclusões: 4 · com prova no código do app: 0

O que falta (reprova):
  ✗ Falta a seção "## O que NÃO deu para provar". Peça ao agente: "liste o que você acha mas não achou no código".
  ✗ "C1. O app usa uma arquitetura moderna baseada em microsserviços": conclusão sem prova. Falta o arquivo/trecho (ex.: `src/arquivo.ts:40-62`).
  ✗ "C4. Dá para refazer tudo em uma tarde": conclusão sem prova. Falta o arquivo/trecho (ex.: `src/arquivo.ts:40-62`).
  ✗ Todas as referências apontam para bibliotecas (node_modules, vendor, site-packages...). Mande o agente ignorar essas pastas e provar no código do app.

Avisos (não reprova, mas melhore):
  ! "C2. A grade de agentes é feita com uma biblioteca de layout": só cita biblioteca embutida; mostre onde o PRÓPRIO app usa isso.
  ! "C3. As animações deixam a experiência fluida e profissional": só cita biblioteca embutida; mostre onde o PRÓPRIO app usa isso.
  ! Sem a linha "Licença:" em "## Alvo". Confira se você pode estudar esse app.

O exemplo bom (exemplos/provas-boa.md) sai NOTA 10/10 — APROVADO. Os dois usam um app fictício para mostrar o formato.

O que você precisa

O conferidor roda em qualquer computador com Python. O REA é opcional: ajuda o agente a enxergar apps e sites por dentro.

Python 3.8 ou mais novo

Para o conferidor e os testes. Confira:

python3 --version

Um agente de IA no terminal

Passo a passo

Do zero até a sua versão

Comandos para Linux, Mac ou WSL. No Windows sem WSL, troque python3 por py.

1

Baixe o kit

Clona o repositório na sua pasta pessoal e confere que o conferidor funciona. Os passos seguintes usam esse caminho.

cd ~   # o kit fica na sua pasta pessoal: ~/rea-com-provas
git clone https://github.com/inematds/rea-com-provas.git
cd rea-com-provas
python3 -m unittest discover tests   # deve terminar com OK
2

Escolha o alvo e confira a licença

Um app open source (baixe o código) ou o seu próprio site. Abra o arquivo de licença antes de qualquer coisa.

git clone https://github.com/[dono]/[app-open-source].git ~/estudo/app
cat ~/estudo/app/LICENSE   # MIT, Apache-2.0, BSD, GPL…? então pode estudar
3

Preencha o brief de design

Copie o modelo e troque os [colchetes]: cores com código, fontes, movimento e densidade. O modelo já traz um exemplo preenchido no padrão INEMA.

cp brief/MODELO-brief-design.md ~/estudo/brief.md
4

Cole uma das 3 construções no agente

Abra o arquivo em prompts/, troque os [colchetes] e cole o bloco de texto no seu agente, aberto na pasta do estudo. Ele faz só a fase 1 (estudar) e para.

cd ~/estudo
claude   # ou: codex — e cole o texto de prompts/a-painel-de-agentes.md
5

Confira o provas.md

O próprio pedido manda o agente rodar o conferidor. Rode você também: é o seu "peça a prova".

python3 ~/rea-com-provas/confere_provas.py provas.md
python3 ~/rea-com-provas/confere_provas.py provas.md --json   # mesmo resultado em JSON

REPROVADO? Cole a lista "O que falta" de volta no agente e peça para corrigir. Abra 2 ou 3 provas no editor e veja se o trecho está mesmo naquela linha: o conferidor checa o formato, quem confere o conteúdo é você.

6

Libere a construção

Só com APROVADO. Escreva no agente:

pode construir

No fim, ele diz como abrir, o que ficou de fora e o que precisa de teste manual.
